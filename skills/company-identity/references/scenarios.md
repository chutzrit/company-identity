# 상황으로 기준 검증하기

문서가 보기 좋게 정리됐는지보다 실제 선택에 쓸 수 있는지 확인한다.

## 질문 만들기

회사의 실제 사업과 인터뷰 답변으로 짧은 상황을 만든다. 보통 아래 세 유형이면 첫 검증에 충분하다. 사용자에게는 한 번에 1~3개만 묻는다.

| 유형 | 확인할 것 |
|---|---|
| 가치 충돌 | 품질·속도·가격·성장 등이 충돌할 때 무엇을 먼저 지키는가 |
| 지양점의 경계 | 매력적인 수익·기회가 있어도 거절하거나 수정할 조건이 있는가 |
| 정보 부족 | 가격·효과·근거·승인 등이 부족할 때 무엇부터 확인하는가 |

“과장은 나쁘니 하지 않는다”처럼 답이 뻔한 질문만 내지 않는다.
예를 들어 자립을 우선한다는 회사라면, 매출이 큰 장기 대행과 작은 교육형 납품 중 어느 쪽을 선택할지, 어떤 조건에서는 예외가 되는지 묻는다.

각 질문에는 사업 맥락 한 문장과 서로 다른 합리적인 답변 예시 2~3개를 `text` 코드 블록으로 붙인다. [인터뷰 예시](interview-examples.md)의 상황 검증 항목을 참고한다. 사용자는 예시를 수정하거나 다른 답을 할 수 있다. 이미 확정한 규칙을 어기는 예시는 정상 선택지로 제시하지 않는다.

## 답변 반영

1. 사용자의 선택과 이유를 받는다. 에이전트가 사용자 역할까지 연기하지 않는다.
2. 현재 문서만으로 같은 결론에 도달하는지 비교한다.
3. 다르게 해석되면 부족한 우선순위나 예외 조건을 보강한다.
4. 수정한 기준을 새 상황 하나에 적용해 모순이 없는지 확인한다. 새 결정이 필요한 부분만 사용자에게 묻는다.

사용자가 이미 충분한 사례와 결정을 제공했다면 그 사례를 검증 근거로 활용한다.
보강 요청에서는 영향받는 기준만 다시 검증한다.
사용자가 검증을 생략하거나 초안만 요청하면 그렇게 진행하고 문서 상태에 남긴다.

## 간단한 결과

- 검증된 선택과 그 기준
- 문서에 반영한 수정
- 결정이 필요한 항목이 있으면 해당 질문

일반적인 좋은 습관만 나열하지 말고 이 회사의 선택이 드러나는지 확인한다.
