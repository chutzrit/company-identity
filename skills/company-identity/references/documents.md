# 회사 문서 작성과 저장

## 기본 파일

새 문서를 만들 때 현재 작업 프로젝트에 `docs/` 폴더를 만들고 다음 경로에 저장한다. 폴더가 이미 있으면 그대로 사용한다. 사용자가 지정한 위치나 기존 문서가 있으면 그 경로를 유지한다.

| 파일 | 내용 |
|---|---|
| `docs/about-company.md` | 고객·존재 이유·비전·가치·우선순위·지양점 |
| `docs/company-rules.md` | 방향성에 근거한 업무 행동·검토 기준·예외 처리 |
| `docs/project-instructions.md` | 회사 기준을 적용하는 작업 순서·검토 방법·원본 문서 경로 |
| `.company-identity.json` | 이 프로젝트에서 읽을 문서 3종의 경로 |

회사 문서를 처음 완성할 때는 결과물 3종을 함께 저장한다. 기본 양식은 [output-templates.md](output-templates.md)를 읽고 실제 인터뷰 내용으로 채운다. 사용자가 범위를 좁혀 요청했다면 해당 문서만 다룬다.

회사 자료를 스킬 설치 폴더나 사용자 전역 스킬 폴더에 저장하지 않는다.
프로젝트 루트는 사용자 작업 폴더 또는 저장소 루트를 따른다. 불명확하면 파일을 만들기 전에 위치만 짧게 묻는다.

## 기존 문서 연결

- 사용자가 지정한 문서가 우선이다.
- 기존 소개서·사규가 목적을 충분히 충족하면 그대로 연결한다. 파일명이나 구조를 억지로 바꾸지 않는다.
- 하나의 문서에 방향성과 사규가 함께 있으면 두 경로를 같은 파일로 지정해도 된다.
- 회사 문서 세트의 준비·보강 요청에서 일부만 있으면 그 문서를 유지하고 부족한 문서만 만든다. 방향성·사규가 충분하면 다시 인터뷰하지 않고 그 내용으로 작업 지침을 작성한다.
- 단순 호출로 기존 자료를 찾은 경우에는 먼저 목적을 확인한다. 개별 기준 수정·업무 수행·결과 검토 요청을 새 문서 생성으로 확대하지 않는다.
- 후보가 여러 회사이거나 확정본이 불명확하면 사용자가 고르게 한다.
- PDF 등 읽기 도구가 필요한 파일은 현재 에이전트가 읽을 수 있는지 확인한다. 접근할 수 없는 내용을 추측하지 않는다.

문서를 새로 저장하거나 기존 문서 연결을 요청받으면 아래 설정을 기록한다. 단순 호출로 기존 문서를 찾았지만 사용 목적을 아직 모를 때는 먼저 목적을 묻는다.

```json
{
  "schema_version": 1,
  "documents": {
    "about": "docs/about-company.md",
    "rules": "docs/company-rules.md",
    "instructions": "docs/project-instructions.md"
  }
}
```

기존 `schema_version: 1` 설정에 `direction`·`rules`만 있어도 정상적으로 읽는다. `direction`은 `about`의 이전 이름이므로 같은 문서로 읽고, 설정을 다시 저장할 때 `about`으로 기록한다. 연결된 기존 파일의 이름은 바꾸지 않는다. `instructions`가 없다는 이유로 설정 오류나 신규 회사로 판단하지 않는다. 작업 지침을 만들었거나 기존 지침을 연결했을 때 그 경로를 추가한다.

경로는 설정 파일이 있는 프로젝트 루트 기준이다.
사용자가 명시적으로 지정한 외부 파일을 참조할 수는 있지만 다른 프로젝트로 자동 탐색하지 않는다.
지원하지 않는 설정 버전, 깨진 경로는 알려주고 복구할 위치를 확인한다. 기존 문서를 빈 문서로 대체하지 않는다.

## 방향성 문서

필요한 부분을 짧게 구성한다.

- 회사·사업 한 줄 소개
- 우선 고객과 해결하려는 문제
- 고객의 현재 해결 방식과 우리를 선택할 이유
- 비전 한 줄: 사용자가 정했거나 고른 문장 그대로. 정하지 않았으면 `미정`
- 존재 이유·현재 제공 방식과 앞으로 만들고 싶은 변화
- 핵심 가치와 실제 행동
- 충돌할 때의 우선순위
- 지양할 일·표현·약속
- 아직 결정하지 않은 내용

자료와 답변에서 확인된 사실을 우선 기록한다. 선택 이유가 아직 검증되지 않았다면 `가설`, 결정하지 않은 정책은 `미정`으로 구분한다. 실제 고객 표현이 제공됐으면 의미를 유지한다. 문서 간 충돌은 사용자에게 확인하고 최신 파일이라는 이유만으로 내용을 확정하지 않는다.

가치에는 `D1`, `D2`처럼 짧은 식별자를 붙일 수 있다. 사규가 어떤 방향성에서 나왔는지 추적하는 데 쓴다.
기존 문서에 식별자가 없다면 제목이나 문구로 연결해도 된다.
식별자와 표의 행 순서는 우선순위가 아니다. 가치끼리의 서열은 사용자가 결정한 경우에만 적는다.

## 업무 사규 문서

원칙마다 적용 상황과 검토 기준이 드러나게 만든다.

| 기준 | 연결된 방향성 | 해야 할 일·피할 일 | 확인할 내용 |
|---|---|---|---|
| 사용자 답변에서 도출한 규칙 | 방향성의 항목 | 실제로 관찰 가능한 행동 | 결과물에서 확인할 근거 |

사업에 맞는 디자인·영업·콘텐츠 등의 적용 예시를 담는다. 모든 팀의 규칙을 억지로 채우지 않는다.
규칙이 충돌할 때의 우선순위와 사용자가 정한 예외 처리도 기록한다.
가격·납기·법적 의무·허가권자를 사용자가 말하지 않았다면 만들어 넣지 않는다.

상황 검증 결과는 문서 하단에 짧게 남긴다.

| 상황 | 선택 | 적용 기준 |
|---|---|---|

검증하지 않은 초안은 `초안 · 상황 검증 전`, 미결 사항이 있으면 해당 항목을 `미정`으로 표시한다.
사용자 답변으로 검증·확인된 범위만 확정으로 표시한다. 빈틈을 추론으로 채워 확정하지 않는다.

## 프로젝트 작업 지침

방향성·사규를 읽은 에이전트가 실제 업무에서 따를 방법을 정리한다. 위 두 문서와 함께 인터뷰의 기본 결과물로 작성한다.

- 적용 범위: 인터뷰에서 확인한 회사·활동과 맡길 업무.
- 작업 시작: 회사 문서를 읽고 이번 요청의 목표·입력 자료·산출물을 파악하는 순서.
- 작업 진행: 해당 회사가 선택한 우선순위와 사규를 실행하는 구체적인 행동.
- 결과 검토: 관련 사규에 근거해 제출 전에 확인할 내용.
- 판단이 필요한 상황: 확정된 확인 조건·예외 처리와 기준 충돌 시 확인 방법.
- 참고 문서: 실제 저장된 회사 방향성·업무 사규의 절대 경로. 파일을 읽어 연결을 확인한다.

범용 문구나 빈 대괄호만 남긴 양식으로 저장하지 않는다. 두 문서에 근거해 해당 회사의 작업·검토 방법을 채우고 새 정책·권한·우선순위를 만들어 넣지 않는다. 미정인 회사 기준은 미정으로 유지한다.
아직 특정 프로젝트가 없으면 회사 업무에 공통으로 쓸 지침으로 완성한다. 미래 프로젝트의 이름·목표·입력 파일을 정하기 위해 인터뷰를 늘리지 않는다. 구체적인 프로젝트 정보가 이미 주어졌다면 그 범위만 반영한다.
회사 문서의 내용을 통째로 복제하지 않는다. 원본을 먼저 읽도록 안내하고 업무에 필요한 적용 방법을 간결하게 적는다. 회사 기준이 변경되면 영향을 받는 작업 지침도 확인한다.

## 저장 전 확인

- 문서 3종에 인터뷰의 같은 결정이 반영되어 있고, 작업 지침의 행동·검토 항목에 회사 기준의 근거가 있는지 확인한다.
- 새 결과물의 빈 입력란은 실제 답변으로 채우거나 필요한 경우 미정으로 정리한다.
- 작업 지침과 `.company-identity.json`에 기록한 경로에서 실제 파일을 읽을 수 있는지 확인한다.
- 저장 후 문서 3종의 경로와 짧은 활용 방법을 안내한다. 별도 템플릿 생성 요청을 다음 할 일로 넘기지 않는다.

## 수정과 보강

- 기존 사실·규칙 중 요청과 관계없는 부분은 유지한다.
- 방향성·사규가 바뀌면 연결된 규칙과 프로젝트 작업 지침에서 영향받는 부분을 함께 확인한다. 기존 작업 지침의 프로젝트 정보와 관련 없는 규칙은 유지한다.
- 사규 하나를 바꾸는 요청을 전체 방향성 변경으로 확대하지 않는다.
- 미정 목록에는 사용자가 보류했거나 현재 작업에 필요한 결정만 남긴다. 보강 과정에서 떠올린 새 상품·정책·사업 가능성을 추가 과제로 만들지 않는다.
- 초안 제안과 이미 확정된 내용을 구분한다.
- 새 결정을 받았으면 같은 내용의 승인을 반복 요청하지 않고 반영한다.
- 파일을 실제로 저장한 후 경로와 핵심 변경만 알려준다.

## 다음 호출에서 다시 읽기

`.company-identity.json`은 이 스킬이 회사 문서를 다시 찾기 위한 경로 기록이다. 스킬을 다시 호출하면 연결된 문서 3종을 읽고 보강하거나 요청 업무에 참고한다. 이전 설정에 작업 지침이 없으면 연결된 방향성·사규를 우선 사용한다.
