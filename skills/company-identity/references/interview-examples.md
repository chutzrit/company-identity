# 회사 방향성 인터뷰 예시

AI 교육 사업을 가정해 작성한 대화 예시. 실제 인터뷰 기록이 아니며, 업종·답변·규칙을 사용자의 사실로 가져오지 않는다.

## 1. 사업과 고객 파악

에이전트

```text
어떤 일을 하나요? 누구에게 무엇을 제공하는지 편하게 적어 주세요.
```

사용자

```text
AI 도구를 가르치는 온라인 강의를 준비하고 있어요.
대상은 도구를 써 봤지만 자기 업무에 활용하기 어려운 실무자예요.
지금은 기능 소개 영상을 찾아보지만 자기 파일로 결과물을 만드는 데서 막혀요.
내 강의는 자기 업무 자료로 직접 따라 하게 하고 싶어요.
이 방식 때문에 내 강의를 선택할지는 아직 확인하지 못했어요.
```

반영: 사업·고객·학습 방식은 답변대로 기록. 고객의 선택 이유는 가설로 구분. 한 번에 답한 고객의 문제·현재 해결 방식은 다시 묻지 않음.

에이전트의 메시지마다 질문은 하나다. 아래 비전 구체화와 비전 한 줄도 답을 받은 뒤 따로 묻는다.

## 2. 비전 구체화

에이전트

```text
## 질문
강의를 마친 사람이 장기적으로 어떤 일을 할 수 있으면 좋겠나요?

## 상황
강의에서 쓴 도구나 화면이 바뀌면 배운 순서를 그대로 따라 하기 어려울 수 있어요.

## 답변 예시
1. 배운 작업 하나를 안정적으로 반복할 수 있으면 좋겠어요.
2. 도구가 바뀌어도 자기 업무에 맞는 방법을 찾아 시도할 수 있으면 좋겠어요.
3. 팀 동료에게 활용 방법을 설명하고 함께 개선할 수 있으면 좋겠어요.

예시를 고르거나 고쳐 답해 주세요. 다른 답이나 미정도 괜찮아요.
```

사용자

```text
2번이요. 모든 도구를 다루게 하는 것보다 새로운 도구도 스스로 시도하게 하고 싶어요.
```

반영: 비전은 도구 변화에도 스스로 시도하는 실무자. 팀 교육은 별도 목표로 추가하지 않음.

에이전트

```text
## 질문
이 변화를 한 문장으로 적어 둘게요. 이미 쓰는 비전 문장이 있나요?

## 답변 예시
1. 도구가 바뀌어도 자기 업무에 맞는 방법을 스스로 찾아 시도하는 실무자를 늘린다.
2. AI를 써 본 실무자가 자기 업무 자료로 직접 결과물을 만들 수 있게 한다.

쓰는 문장이 있으면 그대로 알려 주세요. 예시를 고치거나 미정으로 두어도 괜찮아요.
```

사용자

```text
아직 없어요. 1번으로 하되 "늘린다"보다 "돕는다"가 좋아요.
```

반영: 비전 한 줄은 “도구가 바뀌어도 자기 업무에 맞는 방법을 스스로 찾아 시도하는 실무자를 돕는다.” 2번 후보의 내용은 합치지 않음.

## 3. 우선순위와 지양점 정하기

에이전트

```text
## 질문
강의 시간이 부족하면 어떤 부분을 먼저 조정할까요?

## 상황
여러 기능을 소개하려다 보니 직접 따라 하는 시간이 부족해졌어요.

## 답변 예시
1. 기능 수를 줄이고 직접 결과물을 만드는 시간을 확보할래요.
2. 기능은 모두 소개하고 따라 하는 과정은 별도 자료로 제공할래요.
3. 전체 개요를 보여 주고 참석자에게 필요한 기능을 골라 실습할래요.
```

사용자

```text
1번이요. 이 실무 강의에서는 기능 개수보다 직접 써 보는 게 우선이에요.
그리고 소개문에서 누구나 바로 업무 시간이 줄어든다고 보장하고 싶지는 않아요.
확인한 사례와 결과가 달라질 조건을 같이 적고 싶어요.
```

반영: 실무 강의의 우선순위와 효과 표현의 기준을 기록. 모든 교육 형식에 같은 시간 구성을 강제하지 않음.

## 4. 초안 확인

에이전트

```text
## 정리한 방향성
- 고객: AI를 써 봤지만 자기 업무에 적용하기 어려운 실무자
- 제공 방식: 자기 업무 자료로 직접 결과물을 만드는 강의
- 비전 한 줄: 도구가 바뀌어도 자기 업무에 맞는 방법을 스스로 찾아 시도하는 실무자를 돕는다.
- 우선순위: 실무 강의에서는 기능 소개 개수보다 직접 해 보는 경험
- 지양점: 모든 수강생에게 같은 효과가 난다는 보장

## 업무 기준
- 시간이 부족하면 소개할 기능을 줄여 직접 해 보는 시간을 확보한다.
- 효과를 소개할 때는 확인한 사례와 결과에 영향을 주는 조건을 함께 적는다.

## 가설
- 자기 업무 자료로 따라 하는 방식이 강의 선택 이유가 될 수 있다.

답변과 다르게 정리된 부분이 있으면 알려 주세요.
```

사용자

```text
맞아요. 그렇게 정리해 주세요.
```

## 5. 상황 검증

에이전트

```text
## 상황
핵심 작업을 따라 하려면 사전 설정에 시간이 많이 필요해요.
설정을 모두 설명하면 결과물을 만들 시간이 부족해져요.

## 질문
어디까지 직접 해 보게 할까요?

## 답변 예시
1. 설정부터 직접 하되, 이번 강의의 결과물 범위를 줄일래요.
2. 준비된 환경을 제공해 핵심 작업을 직접 해 보게 하고, 설정법은 별도 안내할래요.

예시를 수정하거나 다른 방법을 제안해도 괜찮아요.
```

사용자

```text
2번이요. 설정 자체가 학습 목표가 아니라면 준비된 환경을 써도 돼요.
핵심 작업은 직접 하도록 해 주세요.
```

에이전트

```text
그럼 설치와 설정 자체를 배우는 강의라면, 설정을 대신 준비하기보다
직접 설정해 보는 것을 핵심 작업으로 잡으면 될까요?
```

사용자

```text
네. 그때는 설정을 직접 해 보는 게 핵심이에요.
지금까지 정리한 내용으로 문서를 저장해 주세요.
```

## 문서에 반영할 기준

| 방향성 | 업무 사규 | 결과에서 확인할 내용 |
| --- | --- | --- |
| 스스로 시도하는 실무자 | 강의의 핵심 작업은 수강생이 직접 수행하도록 구성 | 핵심 작업을 직접 하는 단계가 있는가 |
| 실무 강의의 직접 경험 우선 | 시간이 부족하면 소개할 기능을 줄임. 설정이 학습 목표가 아니면 준비된 환경 활용 가능 | 시간 구성과 환경 준비 방식이 학습 목표에 맞는가 |
| 근거 있는 효과 설명 | 확인한 사례와 결과에 영향을 주는 조건을 함께 표시 | 소개문에 사례·조건이 있고 일률적인 효과 보장이 없는가 |

프로젝트 작업 지침에는 핵심 작업을 먼저 정하고 직접 수행할 단계가 있는지 검토하는 방법, 효과 표현의 사례·조건을 확인하는 방법, 두 회사 문서의 실제 경로를 담는다.

위 내용은 이 예시의 답변에서 나온 기준이다. 실제 저장 시에는 현재 사용자의 답변으로 `docs/about-company.md`, `docs/company-rules.md`, `docs/project-instructions.md`를 함께 작성한다.
