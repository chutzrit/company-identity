# Company Identity

우리 회사의 방향성을 정리하고, AI가 그 기준에 맞춰 일하도록 만드는 스킬.

`인터뷰 → 방향성 정리 → 업무 사규 작성 → 상황별 검증`

## 이런 작업에 사용하세요

- 회사·1인 사업의 고객, 비전, 가치와 지양점을 정리할 때
- 기존 소개서·사규를 보강하거나 방향을 바꿀 때
- 회사 기준에 맞춰 제안서·콘텐츠·디자인 작업을 할 때
- 결과물이 회사 기준을 지켰는지 검토할 때

## 설치하기

프로젝트 폴더를 열고 에이전트에게 요청하세요.

```text
company-identity를 현재 프로젝트에 설치해 줘.

## 요청 사항
- 아래 저장소의 INSTALL.md를 읽고 설치해 줘.
- Claude Code와 Codex에서 같은 스킬 원본을 사용하도록 연결해 줘.
- 두 에이전트 경로에서 스킬과 참고자료를 읽을 수 있는지 확인해 줘.

## 설치 정보
- GitHub 저장소: https://github.com/chutzrit/company-identity
```

### 권장: 프로젝트에 설치

| 범위 | 적합한 경우 |
|---|---|
| 프로젝트 설치 · 권장 | 회사별 작업 공간에서 문서와 스킬을 함께 관리 |
| 전역 설치 · 선택 | 여러 프로젝트에서 같은 스킬을 자주 사용 |

전역 설치는 모든 프로젝트에서 스킬을 꺼내 쓰는 방식입니다.
회사 문서와 경로 설정은 어느 방식이든 각 프로젝트에 따로 둡니다.

설치는 스킬 원본 하나를 두고 각 에이전트가 같은 원본을 읽도록 연결합니다.
기본 연결 대상은 Claude Code와 Codex입니다. 다른 에이전트는 해당 프로그램의 스킬 지원·설치 경로를 확인해 추가할 수 있습니다.

## 바로 시작하기

| 사용하는 프로그램 | 입력 |
|---|---|
| Codex | `$company-identity` |
| Claude Code | `/company-identity` |
| 스킬 선택 UI가 있는 앱 | `company-identity` 선택 |

괄호 없이 이름만 호출하면 됩니다. 새로 설치한 스킬이 보이지 않으면 새 대화나 세션에서 확인하세요.

| 현재 상태 | 시작되는 작업 |
|---|---|
| 회사 문서가 없음 | 짧은 인터뷰 |
| 회사 문서가 있음 | 현재 내용을 읽고 보강·방향 전환·점검 중 목적 확인 |
| 인터뷰 중간에 저장한 초안이 있음 | 빠진 내용부터 이어서 정리 |
| 이름 뒤에 업무 요청을 입력함 | 회사 문서를 읽고 해당 업무 수행 |

## 사용 예시

아래는 Codex 입력 예시입니다. Claude Code에서는 첫 부분을 `/company-identity`로 바꾸세요.

### 처음 만들기

```text
$company-identity
```

### 기존 문서로 시작하기

```text
$company-identity 회사 소개는 docs/about.md, 사규는 docs/rules.md에 있어.
이 문서를 기준으로 연결하고 부족한 부분만 인터뷰해 줘.
```

### 특정 기준 보강하기

```text
$company-identity 영업 제안에서 해도 되는 약속과 피해야 할 표현을 보강해 줘.
```

### 회사 기준으로 업무하기

```text
$company-identity 우리 회사 기준에 맞춰 신규 고객에게 보낼 서비스 소개문 초안을 써 줘.
```

### 결과물 검토하기

```text
$company-identity drafts/proposal.md가 우리 회사 방향성과 사규에 맞는지 검토하고 수정해 줘.
```

## 만들어지는 문서

| 파일 | 담기는 내용 |
|---|---|
| `outputs/company-direction.md` | 고객·존재 이유·비전·가치·우선순위·지양점 |
| `outputs/company-rules.md` | 실제 업무 행동·검토 기준·예외 처리 |
| `.company-identity.json` | 이 프로젝트에서 사용할 회사 문서 위치 |

기존 문서가 있다면 그 위치를 유지합니다. 방향성과 사규가 한 파일에 있어도 연결할 수 있습니다.

인터뷰는 한 번에 1~3개 질문으로 진행합니다.
가치·우선순위처럼 답하기 어려운 질문에는 우리 사업에 맞춘 상황과 답변 예시를 함께 보여줍니다. 예시를 고르거나 고쳐도 되고, 다른 답을 해도 됩니다.
마지막에는 실제 업무 상황을 놓고 기준이 충분한지 확인합니다.

## 다른 작업 프로젝트에 연결하기

회사 기준이 필요한 작업 폴더를 열고 해당 폴더의 에이전트에게 요청하세요. 프로젝트마다 한 번씩 연결합니다.

```text
이 프로젝트의 에이전트가 회사 방향성과 사규를 계속 참고하도록,
현재 작업 폴더의 AGENTS.md와 CLAUDE.md를 생성하거나 업데이트해 줘.

## 요청 사항
- 아래 폴더의 company-direction.md와 company-rules.md를 읽어 줘.
- 지침 파일이 있으면 기존 내용을 보존하면서 회사 문서의 실제 경로와 적용 방법을 추가해 줘.
- 파일이 없으면 해당 내용을 담아 새로 만들어 줘.
- 회사 문서 원문을 통째로 복사하지 않고 원본 위치와 참고 방법을 기록해 줘.

## 기록할 적용 방법
- 회사 관련 업무를 시작하기 전에 두 문서 읽기
- 이번 작업과 관련된 회사 기준을 기획·제작과 결과 검토에 적용하기
- 프로젝트 요구사항과 회사 기준이 충돌하면 사용자에게 확인하기

## 작업 후 확인
두 지침 파일에서 회사 문서를 참조할 수 있는지 확인하고, 추가·수정한 내용을 보여 줘.

## 문서 위치
- 회사 문서 폴더: [outputs 폴더의 전체 경로]
```

## 호환 범위

- 공통 `SKILL.md`와 Markdown 지침으로 동작합니다.
- 실행에 별도 API 키·MCP·다른 스킬이 필요하지 않습니다.
- 파일 읽기·쓰기는 사용하는 에이전트의 기능과 권한을 따릅니다.
- 에이전트마다 호출 표시와 응답 품질은 다를 수 있습니다.
